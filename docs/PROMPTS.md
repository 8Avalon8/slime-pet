# 复刻提示词

**中文** · [English](PROMPTS.en.md)

这个项目是和 AI 编程助手（Claude Code）一起做出来的：作者几乎没手写代码，全程用中文描述需求、上手测试、反馈问题。这份文档把那个过程整理成一组提示词，你可以交给自己的编程助手，复刻一个属于你的版本：换个形象、换块屏幕，或者只挑几个功能。

每个阶段都列了两样东西：
- **验收标准**：做到什么程度才算完成；
- **已知的坑**：我们实际踩过、从代码里看不出来的问题。提前把它们告诉助手，能省下好几轮来回。

## 怎么用

1. 先把**总提示词**发给助手，让它知道整体目标和工作方式。
2. 再按阶段**一条一条**发。每个阶段做完都要在真机上验证，确认之后再进下一个。不要一次全塞进去：硬件项目的问题，大多只有烧到板子上才会暴露。
3. 遇到"不灵""卡了"这类说不清的问题时，先让助手**加记录、量数据**，再改。这个项目里最难缠的几个问题，都是靠记录数据才找到真正原因的（见文末"工作原则"）。

## 总提示词

```text
我有一块 ESP-Mosaico 开发板（ESP32-S31，480×480 AMOLED，触摸，BMI270 IMU，ES8311 音频，
振动马达，电池电量计），可选交互模块（按键、人体感应、光线、6 颗彩灯）和摄像头模块。
官方 BSP 在 https://github.com/esp-mosaico/esp-mosaico-bsp，需要 ESP-IDF 6.2 以上（master）。

我想做一只住在屏幕里的桌面宠物史莱姆：复古 RPG 风格，软软的果冻质感，有多种表情和状态，
并且和我正在用的 Claude Code 联动（思考、干活、等我批准时有不同的样子）。

工作方式：
- 每一步做完都要编译、烧录、在真机上验证，再告诉我需要我做什么（看屏幕、按按键、插拔模块）。
- 问题说不清楚时，先加日志或记录接口量数据，再改代码；不要凭感觉调阈值。
- 改动不要一次太大；提交前先问我。
- 音乐和美术都要原创，不要复刻任何游戏的旋律或素材。
- 用中文和我交流。
```

## 阶段 1：渲染核心和电脑端预览

```text
先不碰硬件。用纯 C 写一个不依赖 ESP-IDF 的渲染核心：
- 一个小型光栅库（抗锯齿填充、渐变、描边、alpha 混合），画到 RGB565 帧缓冲；
- 史莱姆状态机：发呆、打招呼、被戳（左右）、晕、睡觉、思考、等待、升级、受伤、充电、
  融化、金属化、干活，每个状态有自己的表情、动作和小特效（爱心、星星、汗滴、Zzz）；
- 果冻弹簧物理：伸缩、摇摆、着地回弹，状态切换时平滑过渡；
- 复古 RPG 风格的状态窗（名字、Lv、HP 条）和对话框（打字机效果）。
再写一个电脑端程序，用同一份代码输出所有状态的对照图和单帧图，方便不烧录就能看效果。
```

**验收**：对照图里每个状态都能一眼认出来；电脑端测速，一帧 480×480 的渲染时间要远小于 40 ms。

**坑**：
- 先做一个浏览器版设计稿（HTML Canvas）来调形状和动画参数，确定后再移植成 C，比直接在 C 里调快得多。
- 只重绘变化的区域（脏矩形），否则在单片机上跑不到流畅帧率。

## 阶段 2：上板跑起来

```text
把渲染核心移植到设备上：帧缓冲放 PSRAM，按脏矩形通过 QSPI DMA 推到屏幕，
渲染分到两个核上并行。帧率、内存占用每隔几秒打印一行统计。
烧录脚本要能在固件运行时自动让设备进下载模式，不用按键；第一次烧录前先完整备份出厂固件。
```

**验收**：真机 25 fps 以上；拔掉 USB 用电池能开机；统计行里内部 RAM 剩余稳定。

**坑**：
- **电池供电开不了机**：板子的 GPIO57（PWR_SW）低电平表示关机。原厂引导程序上电就会把它拉高，标准 IDF 引导程序不会。要用 `bootloader_components` 钩子在引导程序一开始就拉高。新增引导程序组件后，必须删掉 `build/bootloader` 才会被编进去。
- **USB 串口**：TinyUSB CDC 是高速口，接收回调里必须把数据一次读空，否则会永久停收，连自动进下载模式的暗号都收不到。macOS 上新打开的串口默认开着回显，会把设备日志回灌给设备，电脑端要先设成 raw 模式，关闭前还要 `tcdrain`。
- **内部 RAM 是瓶颈**：BSP 默认让屏幕 DMA 经内部 RAM 中转。接上 Wi-Fi 和摄像头之后，内存碎片化会导致屏幕传输报错。要给 BSP 打补丁，开启 `psram_dma_direct`；同时关掉 Wi-Fi 的 IRAM 优化，把 Wi-Fi 接收缓冲压小。
- 不要随手用"只备份不烧录"的模式：它会把芯片留在下载模式，屏幕一直是黑的。

## 阶段 3：接上 Claude Code

```text
在电脑上写一个 Claude Code 钩子脚本（只用 Python 标准库），把会话事件
（开始、提问、调用工具、工具成功/失败、请求权限、结束）转成一行简单的文本协议发给设备。
设备端跟踪多个会话的状态，决定史莱姆该显示什么，并在对话框里显示 Claude 正在做什么
（工具名、文件名、命令要点）。任务完成加经验值，攒够了升级，等级存起来。
钩子必须异步、不能有任何标准输出、永远返回 0，设备不在线时静默失败。
```

**验收**：真用 Claude Code 干活时，史莱姆的状态和对话框能实时跟上；同时开两个会话也分得清。

**坑**：
- `UserPromptSubmit` 和 `SessionStart` 钩子的标准输出会被注入 Claude 的上下文，所以钩子绝对不能打印东西。
- 事件可能乱序到达：给每行带上时间戳，设备端按时间戳去重、排序。

## 阶段 4：Wi-Fi 和网页面板

```text
加 Wi-Fi（mDNS 名字 slime.local）和设备上运行的网页面板：实时状态、全部设置（改了立即生效并保存）、
手动切换状态试听。钩子改成优先走 Wi-Fi，USB 兜底。Wi-Fi 密码由我自己在终端输入、只通过 USB 发给设备，
任何接口都不能把密码读出来。
```

**坑**：
- macOS 解析 `.local` 时会同时查 IPv4 和 IPv6，等不到 IPv6 记录要白等约 5 秒。脚本里只查 IPv4，并缓存设备 IP。
- ESP-IDF 6 去掉了内置的 cJSON，要用组件库里的 `espressif/cjson`。

## 阶段 5：传感器、声音、设置菜单

```text
- IMU：歪过来史莱姆会滑，使劲摇会晕，扣过来放就睡觉。
- 麦克风：拍两下手打招呼，跟着音乐节拍晃；要排除键盘打字声。
- 声音：不同场景有不同的芯片音效，可以关。
- 机身上的设置菜单：长按屏幕打开，分页，触摸调节。
```

**坑**：
- 设备静止时本身就有倾角：倾斜要相对一个缓慢跟随的基线来算。
- 拍手和打字都是"短促的响声"，区别在于拍手前后是安静的，打字是一串连续的敲击。
- 菜单翻页没反应时，先查"点击之后有没有标记需要重绘"。

## 阶段 6：摄像头

```text
接摄像头模块：在设备上做人脸检测（画面不出设备），眼睛跟着人转，盖住镜头躲猫猫，
坐太近提醒，久坐提醒。加一个相机画面模式和右上角预览小窗，方便确认有没有照到人。
摄像头要支持开机后热插拔。
```

**坑**：
- 摄像头的一根数据线和板载 USB-JTAG 共用引脚，要关掉 USB-JTAG。
- 镜头视野很窄，坐在桌前时脸会占画面宽度的六七成：靠"人在画面里移动"的功能（挥手、跟踪）效果很差，靠"脸本身的变化"的功能更合适。
- 热插拔：拔出时驱动释放可能失败，要保留句柄、下次再补删，否则槽位永远被占用。
- 小窗不要和史莱姆的重绘区域合并成一个大矩形推屏，也不要每帧都刷新它，否则帧率会明显下降。

## 阶段 7：脸部互动（歪头、点头、摇头、对视）

```text
用人脸做互动：你歪头它也歪，点头它开心，摇头它委屈，盯着它看会害羞。
先加一个记录接口，把每次检测的原始数值、滤波值、阈值和是否触发都存下来；
我按固定动作做一遍（静止、点头三次、静止、摇头三次），你看数据再定算法和阈值。
```

**坑**（这一阶段返工最多）：
- 人脸模型的 5 个关键点**几乎不随头部转动变化**（小图上的关键点会趋向"平均脸"），用它判断点头摇头基本只是在对噪声起反应。
- 每帧都要认出人脸的方案也不行：一动头，检测就时有时无。
- 最后可用的做法：人脸检测只用来定位"脸在哪"；之后每一帧都对这个区域做行、列亮度投影，用相邻两帧投影的错位算出头的位移。
- 点头是"低下再回来"**一次**，摇头是"左右左"**两次**，要分开判断。
- 阈值要设上下限，而且下限要高于"大动作之后的余晃"。
- 板子旁边的彩灯如果快速闪烁，会在脸上产生明暗变化，被当成运动。

## 阶段 8：音乐和音效

```text
做一个三声部芯片音乐合成器（方波、三角波、噪声），乐谱用 MML 文本写，支持滑音和连音。
原创一套开机曲、提示音和两首空闲时偶尔哼的背景音乐（可以关）。
再移植公有领域的 sfxr 音效引擎，网页面板上可以随机生成音效、试听、替换任意场景的音效。
```

**坑**：
- 一个长音如果拆成两个同音高的音写，每个音都会重新起音，听起来像"多敲了一下"。要有连音语法。
- sfxr 按 44.1 kHz 设计，设备按 48 kHz 输出，要做插值重采样，否则音高和时长都会偏。
- 合成器可以在电脑上单独编译，把所有音效渲染一遍，检查时长和峰值，比上板听快得多。

## 阶段 9：日常功能和功能演示

```text
加时钟（联网对时，按时段问候）、夜间勿扰（静音、关灯、调暗）、番茄钟、玩法说明页，
以及一个两分钟的功能演示：带字幕，开始前倒数 3 秒，方便录视频；演示不能改动真实的等级数据。
```

**坑**：
- 静音要放在音频层统一拦截，不要在每个播放的地方各加一个判断，否则总有漏的。

## 阶段 10：稳定性

```text
让卡死能自动恢复并留下记录：任务看门狗超时就重启；主循环和音频任务也纳入看门狗；
加一块崩溃记录分区，开机读取上次崩溃的任务名和地址，在状态接口里能查到。
```

**坑**：
- 默认的看门狗只打警告不重启，卡死后只能手动断电。
- 设备因为主循环"无限等待"而卡住时，CPU 并不忙，看门狗不会触发；把主循环本身注册进看门狗，才能抓到这种情况。

## 阶段 11：无线更新

```text
做无线固件更新：两个程序位轮流写，新固件跑满 30 秒才确认，在那之前崩溃就自动退回旧版。
更新需要口令，口令只能通过 USB 拿到。改分区表时设置区的位置不能动，烧录前先备份设置区。
```

**坑**：
- 改分区表后，新的分区记录区要写成空白，否则那里残留的旧数据可能让设备启动到一个空分区上。
- 新固件的健康确认不要依赖 Wi-Fi、摄像头这些外部条件，否则它可能永远确认不了，重启一次就被悄悄退回旧版。

## 阶段 12：按键和 AI 点评

```text
把板载的 AI 键、BOOT 键和交互模块的按键都用上（静音、专注、设置、音量）。
再让它用我电脑上的本地模型（LM Studio）在 Claude 每做完一轮工作后，
以史莱姆的口吻点评一句。会话记录只能发给本机模型，不能上传云端。
```

**坑**：
- 钩子有超时限制，而且不能拖慢 Claude：调用模型的部分要放进一个脱离会话的后台进程。
- 设备字库只有预先渲染过的字，模型写出来的字可能显示不了。要么加一张常用字扩展表，要么让电脑端读取设备的字库表、过滤掉显示不了的字。这个项目两样都做了。

## 工作原则

这个项目里最有效的几条经验：

1. **先量再改**：点头识别前后改了好几版。最早几版是凭感觉调阈值，加了记录接口之后才发现：问题先是"关键点根本不随头动"，后来又是"点头只有一次折返"。没有数据，就只能越调越乱。
2. **在电脑上复现**：渲染、合成器、点头算法都能脱离硬件在电脑上跑，用录下来的真实数据回放测试，几秒就能看出一组参数行不行。
3. **同一状态下对比**：测性能时，前后两次的状态不一样（比如一次在充电动画、一次在发呆），数字就会误导人。
4. **让它自己留下证据**：偶发的卡死很难当场抓到，先加崩溃记录，下次发生时就有线索。
5. **全新目录编译一次**：发布前在干净的目录里重新编译，能查出只存在于你本机配置里的设置。
